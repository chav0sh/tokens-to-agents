Embeddings

An embedding turns a text into a list of numbers, so that texts with similar meaning get similar numbers. It is how a program finds "the passage about this" without sharing a single word with it.

The problem

People don't use the document's words

An employee asks: "What do I do if my computer is stolen?" The security policy says: "Report a lost device within 24 hours." No word matches. WHERE text LIKE '%stolen%' returns nothing, and so does a full-text index. You need a search that compares meaning, not letters.

This is the "retrieve" box of chapter 4, opened up. The examples use the same 14 chunks of the handbook listed there.

How it works

Similarity is one number

Two vectors are compared with cosine similarity: the cosine of the angle between them. 1 means the same direction, 0 means unrelated. It is a dot product divided by the two lengths; three lines of code.

Worked: "What do I do if my computer is stolen?"

The question is embedded with the same model, then compared with all 14 chunk vectors:

0.51 7 work from home

0.27

Chunk 8 wins clearly, with no shared word: the model has learned that "computer" is near "laptop" and "stolen" is near "lost". Chunk 10 comes second because it also mentions a laptop.

Read the order, not the number. Chunks that have nothing to do with the question still score up to about 0.5 here, and 0.59 for another question in the eval, where two unrelated chunks tie with the right one. A score has no fixed meaning: 0.6 can be a strong match with one model and a weak one with another. Take the top few results; if you need a cut-off, measure it on your own data.

Four rules that save you a bad day

RuleWhy
Embed questions and documents with the same model.Each model has its own map. Vectors from two models cannot be compared.
Changing the model means re-embedding everything.It is a full reindex, like changing a column's collation.
Know the model's input limit.Text beyond it is silently cut off. This is one reason documents are split into chunks (chapter 9).
Store the model's name next to the vectors.So you can tell, later, which map a vector belongs to.

Use it when, skip it when

What embeddings are good and bad at

Use embeddings when

  • Users describe things in their own words: synonyms, paraphrases, typos.
  • Questions and documents may be in different languages (with a multilingual model).
  • You need "more like this": similar tickets, duplicate questions, clustering.

Skip, or add something, when

  • The query is an exact token: a form number, an error code, a surname. Add keyword search (chapter 7).
  • The question is a filter or a count: "all policies changed in 2026". That is SQL.
  • The whole corpus fits in the prompt. Then just send it.

Embedding models

Run locallyfastembed (this book) · sentence-transformersSmall open models on a CPU. No API key, no cost per call, data stays local.
HostedOpenAI, Cohere, Google and Voyage AI embedding APIsLarger models, paid per token. One more network call per query.
Open model familiesBGE, E5, GTE, all-MiniLMThis book uses BAAI/bge-small-en-v1.5: 384 dimensions, English.
Comparing modelsMTEB leaderboardA public benchmark for embedding models. For the shortlist only; test on your data.

More dimensions can hold finer distinctions and cost more memory per vector. A few hundred is plenty to start with.

In the docs assistant

Inside retrieve(): every chunk gets a vector

import math
from fastembed import TextEmbedding

embedder = TextEmbedding("BAAI/bge-small-en-v1.5")   # downloads once, then runs on CPU

def embed(texts: list[str]) -> list[list[float]]:
    return [[float(x) for x in vector] for vector in embedder.embed(texts)]

def cosine(a: list[float], b: list[float]) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))

chunk_vectors = embed(CHUNK_TEXTS)                     # once, when the documents change
question_vector = embed(["What do I do if my computer is stolen?"])[0]
scores = [cosine(question_vector, v) for v in chunk_vectors]   # 0.73 for chunk 8

For 14 chunks, comparing against every vector in a loop is the whole search engine. It stops being enough at a few hundred thousand chunks, which is the next chapter.
