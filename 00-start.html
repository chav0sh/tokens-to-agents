What AI engineering is

AI engineering is building applications on top of a model that someone else trained. You don't design or train the model. You call it over an API, and your work is everything around the call.

Every AI application is this loop

A model only reads text and writes text. So the app translates in both directions: the user's problem into a prompt, and the model's output into an answer, a JSON object or an action. Retrieval, tools and agents are all ways of making the first box better.

Where you work: the top layer

Application development Prompts, context (retrieval and tools), evaluation, the interface. This book lives here.
Model development Training, finetuning, datasets, making inference faster. One page of this book: chapter 20.
Infrastructure Serving models, compute, data, monitoring. Mostly the back-end work you already know.

You start at the top and move down only when you have to. Many working products never leave the top layer.

What changes from the work you know

Back-end workML engineeringAI engineering
The core partCode you writeA model you train A model someone else trained, behind an API
To change behaviourChange the codeRetrain with new data Change the prompt and the context. Finetune later, if ever
OutputThe same for the same inputA label or a number Open-ended text that can differ between calls
How you know it worksTests pass or failA metric on a test set Evals: scored cases, rerun on every change. The hardest part
What costsYour serversTraining compute Tokens per call, and seconds of waiting

Three differences matter most. You adapt a model instead of training one. The model is big, so each call is slow and costs money. And the output is open-ended, so checking it is a real engineering problem, not an afterthought.

You don't need machine-learning theory to start. You need to know what goes into a model (tokens), how to find the right text to give it (retrieval), how to steer it (prompts), and how to check it (evals). The rest is software engineering.

Read with the app open

The docs assistant is a real, small program in the app folder next to this book: one Python file and one handbook. Most chapters end with a Try it box: a command to run or one line to change. From chapter 4 on, a scoreboard shows how many of 12 test questions the assistant gets right, so you can see what each new piece fixed.

Short on time? Chapters 1, 2, 4, 12, 17 and 21 are the backbone: the model, prompts, RAG, tools, evals and the architecture. Come back for the rest when a project needs it.
