RAG: the whole pattern

Retrieval-augmented generation (RAG) is the most common pattern in AI products: find the few passages that matter, put them in the prompt, let the model answer from them. This chapter shows the whole thing working, and gives it a score. The rest of Part 2 improves one piece at a time.

The problem

The model has never read your handbook

A model knows what was in its training data. Your company's policies were not. There are three ways to get them in:

OptionHowThe catch
Paste everythingSend the whole handbook with every question.Works for a few pages. Beyond that: slow, expensive on every call, and the model loses the one relevant line among thousands.
FinetuneTrain the model further on your documents.Expensive, has to be redone when a policy changes, and the model still cannot say where an answer came from.
Retrieve (RAG)Search for the relevant passages per question; send only those.The answer is only as good as the search. That is what Part 2 is about.

Retrieve, augment, generate: the three words in the name. It is a search engine feeding a template, feeding a model. If you have built search with a results page, you have built two thirds of it.

Step 1: retrieve

The question is "What do I do if my computer is stolen?" Notice that the answer, chunk 8, shares no word with it: the policy says "lost device". A search by meaning (chapter 5) returns the three closest chunks:

Retrieved

  2. 10 · Onboarding guide: new hires get a laptop 0.52
  3. 12 · HR forms: change of address 0.51

The number is a similarity score. The first hit is right; the other two are filler.

Measure it: the scoreboard

One good answer proves nothing. So before improving anything, write down test questions with known answers. Ours are 12 questions, each with the chunk that answers it. Six are phrased in an employee's own words; six ask about a form code.

The score is "the right chunk is ranked first". Eleven of twelve.

The miss is worth a look. Asked "When do I need FIN-140?", the search ranks the chunk about FIN-401 first (0.72) and the right one second (0.69). To a search by meaning, two form codes with the same digits look almost alike. Chapters 7 and 8 fix this, and the scoreboard will show it.

This is the working method of AI engineering. A fixed set of cases, a score, one change at a time. Without it you are tuning by gut feeling. Chapter 17 covers evals in full; from here on, every chapter in this part ends with the scoreboard.

When a RAG answer is wrong, look here first

SymptomCauseWhere to fix it
The right chunk was not retrieved.The search missed it. The most common failure by far.Retrieval: chapters 5 to 9.
The right chunk was retrieved, the answer ignores it.Too many chunks, or a vague prompt.Fewer, better chunks; the prompt (chapter 2).
The answer states something no chunk says.The model filled a gap from memory."Use only the passages", a way out, and a check (chapter 18).
The answer is right but outdated.The index was built from old documents.Re-index when documents change (chapter 9).

Always print the retrieved chunks before you blame the model. If the answer is not in them, no prompt will save it.

Use it when, skip it when

Is RAG the right pattern?

Use RAG when

  • Answers must come from your own documents or data.
  • The content changes: you update an index, not a model.
  • Users need to see the source.
  • Different users may see different documents (filter the search by permission).

Skip it when

  • Everything fits comfortably in the prompt. Send it all; add retrieval when it stops fitting.
  • The answer is a number from a database. That is a query, or a tool call (chapter 12).
  • The task needs no outside facts: rewriting, classifying, translating.
  • You want a different style or skill, not new facts. That is the case for finetuning (chapter 20).

In the docs assistant

Version 3: it answers from the handbook

The whole assistant is one file, app/assistant.py, next to this book, with the handbook in app/handbook.md. This is the heart of it:

SYSTEM = (
    "You answer employees' questions about company policy.\n"
    "Use only the passages below. If they don't contain the answer, say you don't know.\n"
    "Name the document you used."
)

def answer(question: str) -> str:
    chunks = retrieve(question)                                              # 1. retrieve
    passages = "\n".join(f"[{c['doc']}] {c['text']}" for c in chunks)        # 2. augment
    human = f"Passages:\n{passages}\n\nQuestion: {question}\n\nAnswer in one or two sentences, then the source."
    return llm.invoke([("system", SYSTEM), ("human", human)]).content        # 3. generate

Everything else in Part 2 happens inside retrieve().

Try it. From the folder that holds this book:

  1. uv run python app/assistant.py --eval prints the scoreboard. No model or key needed.
  2. uv run python app/assistant.py --explain "When do I need FIN-140?" shows what each search returns for one question.
  3. With a model key set, ask it something: uv run python app/assistant.py "Can I work from home?"
  4. Add a paragraph to handbook.md, add a question for it to EVAL, and run the scoreboard again.
