Finetuning: when you need it

Finetuning means training an existing model further on your own examples, so its behaviour changes. It is the one technique in this book that changes the model itself, and for most application developers it is the last thing to try, not the first. This is a short chapter on purpose.

The problem

"Should we train our own model?"

Every AI project hears this question early, usually as the answer to "the model doesn't know our data". It is the wrong tool for that. The useful question is what kind of failure you have:

The model fails because…ExampleThe fix
It lacks informationIt does not know your policies, or its knowledge is out of date.Give it the information: retrieval (Part 2) or a tool (chapter 12).
It behaves wronglyIt knows enough, but the output has the wrong format, style or level of detail, however you prompt it.A better prompt and examples first. If that is not enough: finetuning.

One of the three books puts it in a line worth remembering: finetuning is for form, and RAG is for facts.

The picture

The order to try things in

Finetuning sits at the end of the line because every earlier step is cheaper, faster to try, and easier to undo.

How it works

What it is, in builder's terms

You collect examples of input and ideal output, usually a few hundred to a few thousand. A training run adjusts the model's weights so that it produces outputs like yours. The result is a new model version that you call like any other.

WordMeaning
Full finetuningAll the weights are updated. Needs serious hardware; rare for application teams.
LoRA (and PEFT in general)The model stays frozen; a small add-on with well under 1% as many weights is trained instead. Far cheaper, and the standard way today. PEFT means "parameter-efficient finetuning".
DistillationA large model produces the examples; a small model is trained on them. The usual reason: the same quality on one task, at a fraction of the cost and latency.
QuantizationStoring the weights with fewer bits so the model fits on smaller hardware. Not training, but it turns up in the same conversations.

What it costs you

CostDetail
DataGood examples are the real expense. The model learns your mistakes as faithfully as your good outputs.
An eval, firstWithout chapter 17 you cannot tell whether the finetuned model is better.
UpkeepWhen a better base model appears, your finetune does not move to it. You train again.
Side effectsA model tuned hard for one task can get worse at others.
ServingA hosted finetune often costs more per token; an open model you tuned has to be run by someone (chapter 3).

Use it when, skip it when

The honest list

Finetune when

  • You need a strict output format or house style that prompting cannot hold reliably.
  • A narrow, high-volume task could run on a much smaller, cheaper model: classification, extraction, routing.
  • The task is in a language, dialect or notation the model handles poorly.
  • The prompt has grown huge with examples, and you pay for it on every call.

Do not finetune when

  • The problem is missing or changing facts. Use retrieval; you update an index in minutes.
  • You have not yet tried a better prompt, examples, or a stronger model.
  • You have no eval and no set of good examples.
  • Users need to see where an answer came from. A finetuned model cannot cite what it absorbed.
