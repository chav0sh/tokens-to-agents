LangChain

LangChain is the library this book has been using since chapter 1 without introducing it. It is the best-known name in AI development and also the most misunderstood: it is not a model, not a database and not required. It is a set of common interfaces, and a very large collection of adapters.

The problem

Every provider speaks its own dialect

OpenAI, Anthropic, Google and NVIDIA all offer "send messages, get a reply, maybe with tool calls". The request shapes, field names, tool formats and error types all differ. So do the clients for Qdrant, Pinecone and pgvector. Code written against one of them is glue you rewrite when you switch, and chapter 3 said you will switch.

The picture

One interface per kind of part

Your applicationThe docs assistant: retrieve, prompt, call, check.

Integration packageslangchain-openai · langchain-anthropic · langchain-google-genai · langchain-nvidia-ai-endpoints · langchain-qdrant · hundreds more. One adapter each.
The actual servicesModel APIs, vector databases, search engines, document loaders.

If you know an ORM or a database driver interface (Go's database/sql, Rails' ActiveRecord adapters), this is the same move: code against the interface, swap the driver.

The pipe: chaining pieces

Every LangChain piece is a "runnable": it has invoke, batch and stream. The | operator connects them, the output of one becoming the input of the next, like a Unix pipe:

from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "Rewrite the employee's question as a short search query. Reply with the query only."),
    ("human", "{question}"),
])
chain = prompt | llm | StrOutputParser()       # template -> model -> plain string

chain.invoke({"question": "hey, so my laptop got nicked on the train yesterday, what now??"})
'laptop stolen train yesterday report police insurance claim'

This is query rewriting from chapter 8, in three lines. Look at the output, though: the model added "police insurance claim", which the employee never said. A rewritten query can drift, so it needs the same scoreboard as any other change.

A ready-made agent

The loop written by hand in chapter 13 also comes prebuilt:

from langchain.agents import create_agent

agent = create_agent(llm, tools=[search_handbook, holiday_days_left], system_prompt=AGENT_SYSTEM)
result = agent.invoke({"messages": [("user", "I'm Tom Ek. How many holiday days do I have left?")]})
ai: tool call holiday_days_left(employee='Tom Ek') tool: Tom Ek has 18 holiday days left this year. ai: Tom Ek, you have 18 holiday days left this year. (Source: holiday_days_left)

The same three messages your own loop produced. Underneath, create_agent builds a LangGraph graph, which is the next chapter.

The family

NameWhat it is
langchain-coreThe interfaces: messages, prompts, tools, runnables. Small and stable.
langchainReady-made pieces built on the core, such as create_agent.
langchain-<provider>One package per integration. You install only the ones you use.
LangGraphFlows as graphs with saved state (chapter 15). A separate library that works with or without the rest.
LangSmithA hosted product for tracing, evals and prompt versions (chapters 17 and 19). Optional and paid beyond a free tier.

Use it when, skip it when

Take the interfaces, be careful with the rest

Use it for

  • One interface over several model providers, so a model switch is configuration.
  • Structured output and tool calling without writing each provider's format yourself.
  • Access to an integration somebody already wrote.

Think twice when

  • You use one provider and make simple calls. Its own SDK is less to learn and to debug.
  • A ready-made chain hides the prompt it sends. If you cannot see the prompt, you cannot fix the answer.
  • You follow a tutorial or a book from a year or two ago. The library changed a great deal between versions, and old import paths and class names often no longer exist.

Pin your versions. AI libraries move fast and break names. A lock file (uv.lock, like Gemfile.lock or go.sum) is what keeps a working app working. The code in this book ran on langchain 1.4 and langgraph 1.2.

In the docs assistant

What the assistant takes from LangChain

UsedNot used
The chat model class, messages, @tool, bind_tools, the prompt template.Ready-made retrieval chains, document loaders, vector store wrappers, memory classes.

The line is deliberate: LangChain where it removes provider differences, plain Python where the logic is the product. Retrieval is where the scoreboard is won, so it stays in code you can read.

Try it. If you have a key for another provider, install its package and replace ChatNVIDIA(...) in app/assistant.py with that provider's chat class. Nothing else should need to change. Then rerun a question.
