Keyword search: BM25

BM25 is the classic formula for ranking documents by the words they share with a query. It is decades older than embeddings, it is what Elasticsearch runs by default, and it is exactly right where vector search is weakest: codes, names and rare terms.

The problem

To an embedding, FIN-140 and FIN-401 are twins

The scoreboard's one miss: "When do I need FIN-140?" Vector search put the FIN-401 chunk first (0.72) and the right chunk second (0.69). An embedding captures what a text is about, and both chunks are about a finance form. The exact digits barely move the vector.

A person searching for a form number, an error code, a product SKU or a surname wants the exact string. That is a different kind of search.

The picture

An inverted index: from word to documents

  1. Text"… using form FIN-140."
  2. Tokenizelowercase, split, drop common words
  3. Tokensusing · form · fin · 140
  4. Inverted indexeach word points to the chunks that contain it

The same structure as the index at the back of a book. A lookup touches only the rows for the query's words, so it is fast at any size.

How it works

Three ideas in one formula

IdeaMeaning
Rare words count moreA match on 140 (one chunk has it) says far more than a match on form (half of them do). This weight is called IDF, inverse document frequency.
Repeats count, with a ceilingA word appearing twice is a stronger sign than once, but ten times is not ten times stronger.
Long documents get no free pointsA long chunk contains more words by chance, so its matches are scaled down.

For each word of the query that the chunk contains, multiply the word's rarity by its frequency part, and add them up:

score = Σ rarity(word) × frequency_part(word, chunk) rarity = ln( (N − n + 0.5) / (n + 0.5) ) N chunks in total, n contain the word frequency_part = f × 2.5 / ( f + 1.5 × (0.25 + 0.75 × length / average_length) )

With the usual settings k1 = 1.5 and b = 0.75. f is how often the word appears in the chunk.

And where it fails

BM25 only sees letters. It has no idea what a word means:

QuestionBM25 returnsWhy
What do I do if my computer is stolen?Nothing at all.The policy says "laptops" and "lost device". No shared word.
How much time off do I get for a new baby?"New hires receive a laptop…"It matched the word "new".
What do I earn for extra hours?"…lost device within 24 hours."It matched "hours". The overtime chunk says "hourly".

The tokenizer is half the result

ChoiceEffect
The same tokenizer for documents and queriesOtherwise "FIN-140." never matches "fin-140".
Stop words (the, is, for, …)Dropped here. With them kept, an early run of this app ranked a chunk second purely because it shared "is" and "for" with the question.
Stemming (laptops → laptop, hourly → hour)Not done here, which is why "hours" missed "hourly". Search engines do it per language.
How codes are split"FIN-140" became fin + 140. Keeping it whole would make it even more exact.

Use it when, skip it when

Where keywords win

Use keyword search when

  • Queries contain identifiers: codes, part numbers, error messages, names, legal references.
  • The vocabulary is specialised, and an embedding model may never have seen the terms.
  • You need to explain a result: "it matched these words" is easy to show.

Don't rely on it alone when

  • People ask in their own words. Six of our twelve questions do, and it gets one of them.
  • Questions and documents are in different languages.
  • Queries are long and conversational: many common words, little signal.

In the docs assistant

A second search, next to the first

import re
from rank_bm25 import BM25Okapi

STOP_WORDS = {"a", "an", "and", "are", "do", "for", "i", "is", "my", "of", "the", "to", "what", "when", ...}

def tokenize(text: str) -> list[str]:
    return [word for word in re.findall(r"[a-z0-9]+", text.lower()) if word not in STOP_WORDS]

bm25 = BM25Okapi([tokenize(chunk["text"]) for chunk in CHUNKS])     # the index: built once, in memory

def keyword_search(question: str) -> list[tuple[int, float]]:
    scores = bm25.get_scores(tokenize(question))
    best = sorted(range(len(CHUNKS)), key=lambda i: scores[i], reverse=True)[:3]
    return [(i + 1, float(scores[i])) for i in best if scores[i] > 0]   # no shared word: not a result
