Prompts

The prompt is the only input the model has. Your program writes it fresh for every request, from fixed parts and found parts. This chapter is about what goes in, in what order, and how to fit it in the window.

The problem

A bare question gets a confident guess

Send the model only "How long is parental leave?" and it answers fluently, from what it read on the internet during training. It does not know your company, so the answer is about some average company. It will not tell you that. A model with nothing to go on does not say "I don't know" unless you make that an allowed answer.

Everything the model should know or obey has to be in the text you send: the rules, the facts, the question, and the shape of the answer you want.

The picture

A prompt is a document your code assembles

You answer employees' questions about company policy.
Use only the passages below. If they don't contain the answer, say you don't know.
Name the document you used.
InstructionsFixed. The role, the rules, the way out.
Q: Can I carry over unused holiday?
A: Yes, up to 5 days into the next year. [Holiday policy]
ExamplesFixed. Show the format instead of describing it.
[Leave policy] Employees get 12 weeks of paid parental leave.
[Leave policy] Leave must be requested 30 days in advance.
…
ContextChanges per request. Found by retrieval (Part 2). The biggest part.
Question: How long is parental leave?
The questionChanges per request. From the user.
Answer in one or two sentences, then the source in brackets.
RefocusFixed. Repeat what you want, last.

The order is deliberate. Models use the start and the end of a prompt best, and the middle worst. So the rules go first, the request is repeated last, and the bulk of the context sits between them, best passage nearest the question.

How it works

Three techniques and one budget

The three techniques everyone uses

NameWhat you addUse it forCost
Zero-shotInstructions only.The default. Start here.None.
Few-shotA handful of example inputs with the output you want.A format, tone or judgement that is easier to show than to describe.More input tokens. The model may copy the examples too closely.
Chain of thought"Reason step by step, then answer."Problems with several steps: compare, calculate, apply a rule to a case.More output tokens, so slower and dearer.

Why "think first" works: the model writes one token at a time and cannot go back. If the answer comes first, the reasoning after it is only a justification. Ask for the reasoning first and the answer is written with the reasoning already on the page. The same goes for JSON: put the reason field before the answer field.

Many current models have a built-in reasoning mode ("thinking") that does this for you. The thinking tokens are billed as output. For a simple lookup, turn it down.

The token budget, worked

Retrieval found 12 passages of about 700 tokens each. The window is 8,000 tokens. What fits?

PartTokensLeft
The window8,000
Reserved for the answer− 5007,500
Instructions− 3007,200
Examples− 4006,800
The question− 506,750
Passages: 6,750 ÷ 700 = 9 fit− 6,300450 spare

Nine of the twelve passages go in; the three lowest-ranked are dropped. Reserve the answer first: a prompt that fills the window leaves the model no room to reply. Your code does this sum on every request, the way a packet builder respects an MTU.

With a very large window the limit stops being "what fits" and becomes "what helps". More context costs more, takes longer, and buries the useful passage. Send the few best passages, not everything you have.

What makes a prompt work

DoBecause
Say exactly what you want, including length and format.The model fills every gap with a guess.
Give it a way out: "if the passages don't answer, say so".Otherwise it invents an answer.
Mark where each part starts and ends (headings, tags, brackets).It must tell your rules from the pasted text.
Split a big task into smaller prompts.Each one is easier to get right, test and debug.
Change one thing, then measure.A prompt that fixes one case often breaks another. Only an eval shows it (chapter 17).

Prompts are code. Keep them in files, in version control, with a version number. A one-word change can move your accuracy. A prompt edited in place on a server is an untested deploy.

Use it when, skip it when

Which technique, when

Reach for it when

  • Few-shot: the output format keeps drifting, or the task is a judgement call you can show with cases.
  • Chain of thought: the model gets multi-step questions wrong but each step right.
  • A longer prompt: an eval shows a specific failure that a rule or an example fixes.

Skip it when

  • Few-shot: plain instructions already pass your evals. Examples are tokens on every call.
  • Chain of thought: the task is extraction or a lookup, or the model already has a thinking mode.
  • Prompt tricks: the model lacks the facts. No wording fixes missing knowledge; that needs retrieval (Part 2).

In the docs assistant

Version 2: a real prompt

The assistant gets its template. The passages are still pasted by hand; Part 2 replaces that hand with search.

from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system",
     "You answer employees' questions about company policy.\n"
     "Use only the passages below. If they don't contain the answer, say you don't know.\n"
     "Name the document you used."),
    ("human",
     "Passages:\n{passages}\n\n"
     "Question: {question}\n\n"
     "Answer in one or two sentences, then the source."),
])

messages = prompt.invoke({
    "passages": "[Leave policy] Employees get 12 weeks of paid parental leave.",
    "question": "How long is parental leave?",
})
reply = llm.invoke(messages)      # llm from chapter 1

Two things to notice. The rules live in the system message and the request is repeated at the end of the human message: start and end, the two places the model reads best. And the user's question fills a hole in a template; it never gets to rewrite the rules above it. Chapter 18 shows why that separation matters.

Try it. Delete the sentence "If they don't contain the answer, say you don't know" and ask something the passage does not cover. Then put it back. That one sentence is the difference between a guess and an honest "I don't know".
