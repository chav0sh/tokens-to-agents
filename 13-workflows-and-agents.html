Workflows and agents

Once a task needs several steps, someone has to decide which steps run and in what order. Either your code decides (a workflow) or the model decides (an agent). This is the most important design choice in an AI system, and "agent" is not automatically the better answer.

The problem

One call is not enough

Maria's question, "I want to take 10 days off next month. Do I have enough holiday left?", needs three things: her balance from the HR system, the holiday rule from the handbook, and a comparison of 7 with 10. No single model call does all three. The steps have to be chained, and something has to hold the chain together.

An agent: the model decides the path

One loop. The model sees the question and the results so far, and chooses the next step itself. This is tool calling from chapter 12, repeated until the model stops asking.

Three model calls, a correct answer, and a search query the model wrote on its own. That is the appeal: you wrote two tools and a loop, and it worked out the rest.

The workflow, and a bug

The workflow uses two model calls: one to route the question, one to write the answer. The first version put the balance and the rule into the prompt and let the model draw the conclusion:

You have enough holiday days left. You have 7 days remaining, and you want to take 10 days, but up to 5 unused days carry over, which would give you 12 days total.

Wrong. The model added the carry-over allowance to the balance and decided 7 covers 10. The facts were all correct; the reasoning over them was not. The fix was not a better prompt. The comparison moved into code:

left = HOLIDAY_DAYS_LEFT[employee]
fact = f"{employee} has {left} holiday days left this year."
if days_requested > left:
    fact += f" That is {days_requested - left} days short of the {days_requested} days asked for."
You have 7 holiday days left, which is not enough for 10 days. [Holiday policy]

The rule from chapter 11 again: anything that has an exact answer (a comparison, a sum, a date, a lookup) is done by code, and the model is handed the result. A workflow makes that easy, because you own every step. In the agent loop, the same mistake could happen on any run, and there is no obvious place to put the fix.

The first five are workflows. Real systems mix them: a workflow whose one hard step is a small agent is a common and sensible design.

Use it when, skip it when

Start with the workflow

Use a workflow when

  • You can draw the steps on a whiteboard. Most business tasks qualify.
  • Cost, response time and behaviour must be predictable.
  • Steps need rules the model must not skip: a permission check, a calculation, an approval.

Reach for an agent when

  • The steps cannot be known in advance: open-ended research, debugging, exploring an unfamiliar system.
  • The model is strong at tool use and you can afford several calls per task.
  • A wrong step is cheap to notice and undo. Read-only tools first; write actions behind a confirmation.

An agent always needs a ceiling. A maximum number of steps, a time limit, a spending limit. A loop that a model controls can run until one of them stops it. Errors also compound: if each step is right 95% of the time, ten steps in a row are right about 60% of the time.

In the docs assistant

Both versions, in full

MAX_STEPS = 5   # an agent loop always needs a ceiling

def agent_loop(question: str) -> str:
    messages = [SystemMessage(AGENT_SYSTEM), HumanMessage(question)]
    model = llm.bind_tools(list(TOOLS.values()))
    for _ in range(MAX_STEPS):
        reply = model.invoke(messages)
        messages.append(reply)
        if not reply.tool_calls:                     # no tool wanted: this is the answer
            return reply.content
        for call in reply.tool_calls:                # run what it asked for, send the results back
            result = TOOLS[call["name"]].invoke(call["args"])
            messages.append(ToolMessage(result, tool_call_id=call["id"]))
    return "I could not finish this within the step limit."
def workflow(question: str) -> str:
    decision = route(question)                       # model call 1: policy, my_holiday or other?
    if decision.kind == "other":
        return "I can only help with company policy and your holiday days."
    passages = search_handbook.invoke({"question": question})
    if decision.kind == "my_holiday":
        passages += "\n[HR system] " + holiday_fact(decision.employee, decision.days_requested)
    return write_answer(question, passages)          # model call 2

The docs assistant keeps the workflow. Its questions fall into three known kinds, and the one step that needs exactness is now in code.
