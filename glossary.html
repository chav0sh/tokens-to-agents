Glossary

Every term this book uses, in one or two lines, with the chapter that explains it. Type to filter.

TermMeaningCh.
AgentA system in which the model decides, step by step, which tool to call next, in a loop.13
ANN (approximate nearest neighbour)Finding the closest vectors quickly by accepting that a few may be missed.6
BM25The standard formula for ranking documents by the words they share with a query.7
Chain of thoughtAsking the model to write its reasoning before its answer.2
CheckpointerIn LangGraph, the part that saves a flow's state after every step.15
ChunkA piece of a document, small enough to search and to fit in a prompt.9
Context windowThe most tokens a model can handle in one call, prompt and answer together.1
Cosine similarityA number saying how close two embeddings point: 1 is the same direction.5
Cross-encoderA model that reads a question and a passage together and scores the pair. Used for reranking.8
CypherThe query language of Neo4j: you draw the pattern of nodes and relationships you want.10
DistillationTraining a small model on the outputs of a large one.20
EmbeddingA list of numbers that represents a text, so that similar texts get similar numbers.5
EvalA fixed set of cases and a way of scoring outputs, rerun on every change.17
Faithfulness (groundedness)Whether every claim in an answer is supported by the context it was given.17
Few-shotPutting a handful of worked examples in the prompt.2
FinetuningTraining an existing model further on your own examples.20
Function callingSee tool calling.12
GatewayOne service in front of all model calls: keys, limits, fallbacks, logging.19
Graph databaseA database of nodes and the relationships between them, built for following connections.10
GraphRAGUsing a graph as a source of context. Covers several designs, from a fixed lookup to a graph built from documents.11
GuardrailA check around the model: on the input, on the output, or on what its tools may do.18
Evaluation-driven developmentWriting the eval cases and criteria before building, as test-driven development writes tests before code.17, 24
HallucinationA fluent statement that is not supported by the facts or the context. The chapters call it an invented answer.2, 17
HNSWThe index most vector databases use: a layered graph of neighbouring vectors.6
Hybrid searchRunning vector search and keyword search together and merging the results.8
Inverted indexA map from each word to the documents that contain it. The structure behind keyword search.7
Judge (model as judge)A second model call that grades an output against a rule you wrote.17
LangChainA library of common interfaces over model providers and tools, with many integrations.14
LangGraphA library for writing a flow as a graph of steps with saved state.15
LLM (large language model)A model that, given text, predicts the next piece of text. You use it as a service.1
LoRAFinetuning a small add-on instead of all of a model's weights.20
MCP (Model Context Protocol)An open standard for offering tools and data to AI apps from a separate server.16
MemoryWhatever an app stores and puts back into the prompt so the model appears to remember.16
PayloadIn a vector database, the data stored next to a vector: text, title, permissions.6
PromptThe full text sent to the model: rules, examples, context and the question.2
Prompt cachingA provider charging less for the unchanged beginning of a prompt.19
Prompt injectionText, typed by a user or hidden in a document, that makes the model follow someone else's instructions.18
QuantizationStoring numbers with fewer bits, to save memory. Applies to vectors and to model weights.6, 20
RAG (retrieval-augmented generation)Retrieve the relevant passages, put them in the prompt, let the model answer from them.4
ReActThe agent loop: reason, act with a tool, observe, repeat.13
RerankerA second, slower model that sorts the candidates a search returned.8
RouterA step that classifies a request so that code can choose the path.13
RRF (reciprocal rank fusion)Merging ranked lists by summing 1 ÷ (60 + rank).8
Semantic cacheA cache that returns a stored answer for a question similar to an earlier one.19
Stop wordsWords too common to help a keyword search, removed before indexing.7
StreamingSending tokens to the user as they are produced.3
Structured outputMaking the model return data that fits a schema.1
System promptThe message that carries your rules, separate from the user's message.1, 2
TemperatureA setting for how much randomness goes into choosing each token. 0 picks the most likely.1
TokenA piece of a word. The unit models read, write, limit and bill by.1
Tool callingThe model replies with the name and arguments of a function; your code runs it.12
Top-k (retrieval)How many results a search returns: TOP_K in the app, 3 by default.6, 8
Top-p, top-k (sampling)Settings that cut unlikely tokens before one is drawn.1
TraceThe timeline of one request, split into its steps.19
Vector databaseA database that stores embeddings and finds the nearest ones fast.6
WorkflowA multi-step flow in which your code, not the model, decides the steps.13
Zero-shotA prompt with instructions and no examples.2
