The architecture, step by step

Twenty chapters each added one piece. This one puts them on a single page and replays how the system grew: which failure asked for each box, and what the box costs. An AI architecture is not designed in one sitting. It is grown, one measured failure at a time.

The problem

The finished diagram tells you nothing about the order

Look at any "reference architecture for generative AI" and you see fifteen boxes. Teams that start by building all fifteen spend months on infrastructure before they learn whether the idea works. Teams that start with one box and add the next when something breaks ship in weeks, and every box they own has a reason. The diagram is the same at the end. The path is the difference.

How it works

Every box has a reason and a price

  1. One model call

    WhyNothing failed yet. This is the idea, working in an afternoon.

    The priceAbout 1 second and a fraction of a cent per question.

  2. A real prompt

    The failureConfident answers about a company it knows nothing about.

    The priceNothing. One paragraph of text.

  3. Retrieval chunks, embeddings, a vector index

    The failureThe model has never read the handbook.

    The priceAn indexing job and a database to keep in step with the documents. About 10 ms per question.

  4. Better retrieval keyword search, fusion, a reranker

    The failureFIN-140 answered with FIN-401. Scoreboard 11/12.

    The priceA second index and a second small model, about 45 ms. Scoreboard 12/12.

  5. Tools and a graph

    The failure"A director's approval": which director? "Do I have enough days left?": that is in the HR system.

    The priceIntegrations with other systems, and their permissions.

  6. A flow with a router

    The failureThe model decided 7 days cover 10. A request for a poem was answered as policy.

    The priceOne more model call per question, about a second, and a classifier to test.

  7. Input and output guards

    The failureA reworded request leaked the prompt. A planted paragraph was repeated as policy.

    The priceA few milliseconds, and some good answers blocked by mistake.

  8. Evals, a run log, a cache

    The failureThe same eval scored 13/14, then 14/14. The provider began rejecting a request that had worked.

    The priceModel calls to run the evals, storage for logs, a cache to keep fresh.

One correction to the replay. The diagram shows evals arriving last because they sit around everything. In the real order of work they came at stage 2: the scoreboard existed before the second search did, and it is what justified stages 3 to 6. Build the measuring before the improving.

The order most teams follow

Chip Huyen's AI Engineering describes the same growth as five steps seen across many companies. They line up with the stages above:

  1. 1. Enhance contextretrieval and read-only tools
  2. 2. Put in guardrailsinputs and outputs
  3. 3. Router and gatewayseveral models, one entry point
  4. 4. Cacheslatency and cost
  5. 5. Agent patternsloops and write actions

With monitoring and orchestration running alongside all five. The order is a tendency, not a rule: follow your own failures.

The answer path

A normal request, but slow: one to several seconds. Stream the tokens to the client so the wait is visible, and set a timeout on every hop.

Indexing

A background job fed by a queue, like any import. Never inside the request.

Evals

A step in CI, like tests. They cost model calls, so run the full set when prompts, retrieval or the model change.

State

Conversations and the run log go in the database you already have. The vector and graph stores hold copies that can be rebuilt.

Identity

The user comes from your login, never from the prompt. Their ID travels into every search filter and tool call.

Secrets

Model keys live in the environment or a secret store, on the server only. Nothing a browser can read.

Use it when, skip it when

How far to go

Add the next box when

  • You can name the failing cases it will fix, and they are in your eval set.
  • The failure is common or costly enough to justify its price in the table above.
  • You have tried the cheaper fix first: the prompt, then the context, then the structure.

Stop when

  • The evals pass and the budget holds. Many useful products stop at stage 2 or 3.
  • The next box solves a problem you do not have yet. A graph database with no relationship questions is only a cost.
  • You cannot say how you would notice if the box stopped working.
